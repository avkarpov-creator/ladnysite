# Ладный сайт — портфолио студии

Статический сайт: главная студии + 4 демо-проекта. Без сборки и зависимостей, отдаётся Nginx в Docker.

```
site/
  index.html            главная студии
  devops/               техническое портфолио
  seo/                  услуга «SEO-продвижение»
  kontent-zavod/        услуга «Контент-завод»
  css/service.css, js/site.js   общие стили и скрипт (согласие, Метрика) страниц услуг
  demo/doma-bani/       «Тёплый сруб» — дома и бани
  demo/avtoservis/      «Мотор-Двор» — автосервис
  demo/salon/           «Студия Лён» — салон красоты
  demo/remont/          «Ровно» — ремонт квартир, калькулятор
  fonts/                шрифты локально (без Google Fonts), fonts.css + woff2
  robots.txt            демо закрыты от индексации
nginx/site.conf         конфиг Nginx внутри контейнера
nginx/host-ladnysite.conf.example   пример для хостового Nginx + certbot
docker-compose.yml
```

## Посмотреть локально

Откройте `site/index.html` в браузере. Ссылки «Ладный сайт» в плашке демо ведут на `/`, поэтому корректно работают только с сервера (или `python3 -m http.server -d site 8000`).

## Версии и публикация на Beget

Ветка `main` хранит желаемую версию сайта. GitHub Actions проверяет ссылки портфолио, sitemap и синтаксис при push и pull request. Публикация запускается вручную после проверки версии.

Один раз клонируйте репозиторий на хостинге в каталог **вне** `public_html`, используя read-only доступ к удалённому репозиторию при необходимости. Запускайте следующие команды из каталога клона, под пользователем с доступом к веб-каталогу:

```bash
git fetch origin main
release=$(git rev-parse --verify FETCH_HEAD)
webroot=/home/s/skipto4w/ladnysite.ru/public_html
git show --no-patch --oneline "$release"
bash scripts/deploy-site.sh "$release" "$webroot"
```

Последняя команда покажет предполагаемые изменения. После проверки примените **тот же SHA**:

```bash
bash scripts/deploy-site.sh "$release" "$webroot" --apply
```

Скрипт публикует только версионируемую директорию `site/` из выбранного коммита и сохраняет файлы хостинга, которых нет в Git. Для отката укажите SHA предыдущего релиза и сначала выполните пробный прогон. Файлы, добавленные после предыдущего релиза и отсутствующие в нём, при таком откате сохраняются. SSH-ключи и локальные данные вебмастера хранятся вне Git. Для публикации нужны Git, Bash, tar и rsync.

## Аналитика и согласие (152-ФЗ)

- Яндекс.Метрика 113935228 грузится только после «Принять» в баннере cookie (выбор в localStorage `ls-consent`, 12 мес.).
- Цели (JavaScript-события): `tg_click`, `phone_click`, `email_click` — их нужно создать в интерфейсе Метрики.
- Политика: `site/privacy/`. Сторонних запросов до согласия нет: шрифты лежат в `site/fonts/`.
